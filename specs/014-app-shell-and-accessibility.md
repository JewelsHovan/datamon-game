# 014: App shell and accessibility

Status: in-progress
Created: 2026-11-12

## Goal
The game looks and behaves like a finished app around the canvas: a real icon in the tab and on the home screen, installable from the browser, a proper link preview when the URL is shared, fullscreen in one step, a friendly screen when something fails, and the game's state announced to screen readers.

## Context
Release readiness, part 2 of 3 (part 1: spec 013, speed and memory; part 3: spec 015, touch and phones). Today `index.html` has a title and a non-blocking font link and nothing else: the favicon request 404s (QA run 2026-11-12), there is no web app manifest, no description or share image, and a failed asset load leaves a black or half-drawn canvas. The canvas is a single unlabeled element. Menus are keyboard-driven already (spec 005), audio has a mute key (M, spec 010), and reduced motion is honored (spec 004).

## Requirements
- R1. Icons: a favicon (SVG or 32 px PNG plus a 16 px one), a 180 px Apple touch icon, and 192 px and 512 px PNG app icons including a maskable variant, made from the game's own art by a script (no hand-made files), crisp at every size.
- R2. Installable: `public/manifest.webmanifest` with name "Compass: Cardinal Clash", short name "Cardinal Clash", `display: fullscreen` falling back to `standalone`, landscape orientation, theme and background colors from the game, the icons above and a start URL of `./`. Chrome reports no installability errors.
- R3. Sharing: a description, `theme-color`, Open Graph and Twitter card tags, and a 1200x630 share image composed from the title art and the four launch fighters by the same script as R1.
- R4. Fullscreen: a FULLSCREEN item on the title menu and the pause menu, and double-clicking the canvas, toggle fullscreen through the Fullscreen API; nothing breaks where the API is missing (the item is hidden).
- R5. Screen readers: the canvas has `role="img"` and an `aria-label` naming the game and the current screen; a visually hidden polite live region announces screen changes and fight moments (round number, FIGHT, K.O., the round and match winner, pause and resume), throttled so it never floods.
- R6. Failure screen: if the game cannot load what it needs (a fighter's atlas, the effects, the font) or throws during startup, the page shows a readable message in the game's style with a Reload button instead of a black or half-drawn canvas; a `<noscript>` message says JavaScript is needed.
- R7. Keyboard and focus: every menu item is reachable with the keyboard (already true; keep it), the pause menu lists the mute key, and the game pauses itself when the window loses focus during a fight (stuck keys are already cleared on blur).

## Acceptance criteria
- [ ] A1. (R1, R3) A pytest (or script check) confirms each icon and the share image exist at the right size, and the PNG icons have hard pixel edges (no semi-transparent pixels outside the maskable safe zone's background). Screenshots of the icons in `specs/evidence/014/`.
- [ ] A2. (R2) A browser check reads `Page.getAppManifest` and `Page.getInstallabilityErrors` over CDP on a production build: no manifest errors, no installability errors; the favicon and every icon URL answer 200.
- [ ] A3. (R3) The built `index.html` has the description, `theme-color`, `og:title`, `og:description`, `og:image` (absolute URL of the live site), `twitter:card=summary_large_image`; a test parses them.
- [ ] A4. (R4) A browser check selects FULLSCREEN on the title menu and sees `document.fullscreenElement` set, then leaves it with the same item from the pause menu; the item is hidden when `document.fullscreenEnabled` is false.
- [ ] A5. (R5) A browser check reads the accessibility tree (`Accessibility.getFullAXTree`): the canvas is an image with a label that changes between title, select and fight, and the live region's text includes "Round 1", "Fight" and "K.O." during a match.
- [ ] A6. (R6) Browser checks: blocking the fighter atlas request shows the failure screen with a Reload button (screenshot); with JavaScript disabled the noscript message shows.
- [ ] A7. (R7) A browser check: blurring the window mid-fight opens the pause screen; the pause screen shows the mute key.
- [ ] A8. No regression: `./dm check` exits 0 and the 001, 003, 005, 008, 009 and 012 browser checks pass; no console errors and no 404s on any screen.

## Out of scope
- Offline play and a service worker.
- Touch controls and phone layout (spec 015).
- Translations.

## Decisions
- Icons and the share image are generated by a script from existing art (the title lettering and the fighters' idle frames), so they stay consistent and can be regenerated.
- `display: fullscreen` with `standalone` as the fallback: it is a game, and fullscreen is what players expect once installed.
- The live region announces only screen changes and big fight moments, not every hit.
